# PR Security Review

Подготовка данных pull request **Azure DevOps Server** к ИИ-ревью безопасности.
Программа **не обращается к LLM**: она клонирует PR (или релиз) и раскладывает данные по рабочему
каталогу, а анализ проводит ИИ-ассистент (Zoo) в редакторе по системному промпту `prompt.md`.

## Рабочий процесс

```
1. положить свои файлы (отчёты, выгрузки) в inputs/            — опционально
2. py main.py --pr-url=https://host/tfs/Coll/P/_git/R/pullrequest/123   — клон + подготовка данных
   (или по частям: py main.py --pr-id 123 --project P --repo R)
3. открыть workspace/pr_123/ в редакторе и попросить Zoo:
       "проведи ревью безопасности по prompt.md"               — анализ ИИ-ассистентом
4. py cleanup.py --pr-id 123                                   — очистка клона и данных PR
```

## Ревью релиза

Тот же рабочий процесс, но по ссылке на релиз (`_releaseProgress?...releaseId=...`):
diff строится **от предыдущего релиза того же артефакта к текущему** — то, что реально поехало
в окружения с прошлого релиза.

```
2. py main.py --release-url=https://host/tfs/Coll/P/_releaseProgress?_a=release-pipeline-progress&releaseId=9186
   (или: py main.py --release-id 9186 --project P)
4. py cleanup.py --release-id 9186                             — очистка данных релиза
```

Рабочий каталог `workspace/rel_<ID>/`:

| Файл                    | Содержимое                                                          |
|-------------------------|---------------------------------------------------------------------|
| `artifacts/<alias>/`    | по каждому git-артефакту релиза: `clone/` (финальный код на релиз), `base/` (версии до релиза), итоговый `diff.patch`, `files.json`, полный `commits.md`, связанные `pull_requests.json/.md`, `info.json` |
| `diff.patch`            | **сводный diff релиза** (все артефакты, с разделителями-заголовками) |
| `files.json`            | сводный список изменённых файлов (`artifact` + `file`)              |
| `commits.md`            | все коммиты релиза по артефактам (постраничный commits API, не зависит от глубины клона) |
| `pull_requests.json/.md`| PR, в которые входили коммиты релиза (если API этой версии ADO Server поддерживает поиск) |
| `release.json`          | метаданные релиза из ADO (артефакты, окружения)                     |
| `work_items.json`       | связанные work items (вкладка 'Work items' в UI)                    |
| `prompt.md` / `context/`| системный промпт и ваши файлы (как у PR)                            |

Для build-артефактов коммит берётся из записи сборки (`sourceVersion`), база — коммит сборки
предыдущего релиза того же артефакта (`artifactSourceId`). Если предыдущего релиза нет — diff
только против первого родителя коммита (выводится предупреждение). Артефакты не-git-типа
(FileShare/NuGet и т.п.) помечаются пропущенными в `state.json`.

`diff.patch` всегда строится напрямую между базовым и финальным коммитами. Поэтому если один файл
менялся несколькими коммитами, в `clone/` и в diff используется именно его последняя версия на момент
релиза; `commits.md` при этом содержит весь интервал `base..head`, а не первые найденные коммиты.

## Что делает main.py

Ссылку на PR из веб-интерфейса можно вставить целиком (`--pr-url=...`) — проект, репозиторий и id
берутся из неё; ветка не нужна (целевая берётся из данных PR).

1. По **id PR** получает из ADO `last_merge_commit` (merge-коммит PR — «целевая ветка + изменения PR»)
   и `last_merge_target_commit` (его база).
2. Клонирует `refs/pull/<ID>/merge` с глубиной 2 (merge-коммит и родители). Если merge-коммита нет
   (PR в конфликте) — выгружает ветку источника и целевую ветку, база = `merge-base`.
3. Готовит рабочий каталог `workspace/pr_<ID>/`:

| Файл          | Содержимое                                                        |
|---------------|-------------------------------------------------------------------|
| `clone/`      | git-выгрузка merge-коммита PR (полный код, состояние после PR)    |
| `diff.patch`  | **diff PR** (база → merge-коммит) — предмет проверки               |
| `files.json`  | список изменённых файлов PR с типами изменений                     |
| `comments.md` / `comments.json` | комментарии PR из ADO (ИИ читает их отсюда)     |
| `prompt.md`   | **системный промпт ревью** (копия `prompts/security_review.md`)    |
| `context/`    | ваши файлы-контекст: кладите сюда в любой момент (до/во время анализа) |
| `state.json`  | сведения о PR для cleanup.py                                       |

Проверяется **только PR**: diff merge-коммита относительно целевой ветки, не весь репозиторий
(полный код в `clone/` ассистент читает точечно, при необходимости). Для релиза — то же, но база
diff равна предыдущему релизу артефакта.

## Системный промпт

Лежит в [`prompts/security_review.md`](prompts/security_review.md) — правьте его под себя;
при каждом запуске `main.py` он копируется в `workspace/pr_<ID>/prompt.md`.
В промпте описано: что проверять (инъекции, аутентификация, секреты, криптография, SSRF и т.д.),
правила (только изменения PR, CWE, работа с комментариями) и формат отчёта `report.md`.

## Куда класть свои файлы (в любой момент)

Варианты — контекст можно добавлять **когда угодно**, не только до клонирования:

1. **Прямо в `workspace/pr_<ID>/context/`** — каталог создаётся при подготовке PR; кладите файлы
   до или во время анализа, скажите ассистенту перечитать каталог. Ничего перезапускать не нужно.
2. **Любой путь на диске** — просто назовите ассистенту в чате файл/папку, он прочитает по пути.
3. **[`inputs/`](inputs/)** — что лежит здесь на момент запуска `main.py`, копируется в `context/`
   автоматически. Файлы из `inputs/` никогда не удаляются.

## Очистка — cleanup.py

```bat
py cleanup.py --pr-id 123       :: рабочий каталог конкретного PR
py cleanup.py --release-id 9186 :: рабочий каталог конкретного релиза
py cleanup.py --all             :: все подготовленные PR и релизы
py cleanup.py --all --dry-run   :: предпросмотр
```

Удаляются только каталоги внутри `workspace/` (клоны, diff, комментарии, context-копии).
`inputs/` и промпты не трогаются.

## Секреты и окружение

| Переменная            | Назначение                                       |
|-----------------------|--------------------------------------------------|
| `ADO_PAT`             | PAT Azure DevOps Server (или `DEPP_BOT_TOKEN`)    |
| `REQUESTS_CA_BUNDLE`  | PEM-корень корпоративного CA (опционально)       |

Настройки (адрес ADO, пути, глубина выгрузки) — в [`config.toml`](config.toml).
Требования: Python 3.11+, `git` в PATH, `pip install -r requirements.txt` (только `requests`).

## Структура

```
pr_security_review/
├── main.py                      # 1) клон PR/релиза и подготовка данных (без LLM)
├── cleanup.py                   # 2) очистка клонов и данных PR/релизов
├── config.toml                  # настройки
├── prompts/security_review.md   # СИСТЕМНЫЙ ПРОМПТ ревью (копируется в prompt.md рабочего каталога)
├── inputs/                      # СЮДА кладёте свои файлы-контекст (отчёты и т.п.)
├── workspace/pr_<ID>/           # рабочий каталог PR (см. таблицу выше)
├── workspace/rel_<ID>/          # рабочий каталог релиза (см. раздел «Ревью релиза»)
├── tests/smoke_local_git.py     # смоук-тесты на локальном git-репозитории
└── src/                         # модули: ado_client (REST ADO + Release API), git_ops, comments, ...
```
